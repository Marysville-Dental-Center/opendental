Branch `port/m2-01`, cut from `m1/integration-a2-patch`. Built in the single-wave run, beside about 55 other packages.

## Sources

Public sources only, as the owner decided. No Open Dental program was installed, observed or decompiled, and no office data was used.

- `OpenDentalDiffDocumentation25-4.xml` and `OpenDentalDiffDocumentation26-1.xml` (what changed in each version: table and column names, column order, types, enum values).
- `OpenDentalDocumentation26-1.xml` (the full 26.1 schema). Used to check the result: 427 tables, and for every table the same column names in the same order with the same types, after the documentation tool's own type normalization (`DocumentationBuilder/Form1.cs`, `GetXElementForColumn`).

The XML documents are not in the repository. To re-run the checks against them, put them in a folder and set `M201_OD_DOCS_DIR` before running `tests/M201Tests`; without it those two tests are inconclusive.

## What was built

### Reference schema

- `OpenDentBusiness/Misc/ForkMigrations/Reference/OdSchema-26.1.70.sql` (new, embedded as `OdSchema-26.1.70.sql`): the full 26.1.70 schema, one `CREATE TABLE` per table, in the same normalized form as the 25.3.48 reference. Every table that differs from 25.3.48 has a comment above it that names each change and says what is `INFERRED`. The backlog suggested `docs/specs/reference/`; it lives next to the 25.3.48 reference instead, because the verifier embeds it and one file avoids two copies drifting apart.
- `tools/New-OdReferenceDatabase.ps1` (new): loads a reference into an empty local database. `-Version 26.1.70` (default) makes `od_261_schema`, `-Version 25.3.48` makes `od_253_schema`. Only 127.0.0.1 or localhost, only databases named `od_<digits>_schema`, and an existing one is dropped only with `-Force` and only when it holds no rows. It checks the table count afterwards (427 or 422).

### Fork migration steps (`OpenDentBusiness/Misc/ForkMigrations/OdParity26_1.cs`, new)

| Level | Step | What |
|---|---|---|
| 2026102401 | `OdParity25_4Schema` | `carrier.PaySuiteTransSup`, `eform.DateTimeSubmitted`, `evaluation.GradeOverride`, `evaluationdef.SchoolCourseDefNum` (+ key), `inseditlog` and `inseditpatlog` `OldValueBig`/`NewValueBig`, `insverify`/`insverifyhist` `DateLastAssigned` date to datetime (the `insverify` key stays), `payterminal.CCIntegration`, `procedurelog.NoBillIns`, `referral.Telephone` varchar(10) to varchar(30), `registrationkey.DateTClinicAccess`, `schoolcoursedef.GradingScaleNum` (+ key), `sheet.DateTimeSubmitted`; new tables `paysuitepayment`, `paysuitepaymentdetail`, `schoolcourseenrollee`, `schoolcourseinstructor`. |
| 2026102402 | `OdParity26_1Schema` | `branding.ValueString` text to mediumtext, `carrier.PreAuthCodes`, `chatuserod.PlayNotificationSound`, `claimproc.Etrans835AttachNum` (+ key), `codegroup.ShowInHistory`/`HistProcCode`/`IsPerioFourQuads`, `definition.Supp`, `dunning.EmailType`, `eformfield.DateTimeSig`, `employee.Title` (+ key), `procnote.UserNum2` (+ key)/`Signature2`/`SigIsTopaz2`, `smstomobile.SecUserNumEntry` (+ key), `statement.IsServiceDateView`; new table `deletedobj`. |
| 2026102403 | `OdParity26_1ClaimPaymentNote` | `claimpayment.Note` varchar(255) to `text NOT NULL`; NULL notes become empty strings first. |

- Every step is idempotent. All the columns and keys a table gains go into one `ALTER TABLE` (`OdParity26_1.AlterTable`), so MyISAM copies a large table (`claimproc`, `procedurelog`, `procnote`) once. Columns already present are skipped, so a partly converted table is finished, not broken.
- Data migrations: `evaluation.GradeOverride` is added with `DEFAULT -1`, so every existing row gets -1 ("no override") in the same statement; `NULL` claim payment notes become `''`. Nothing else is back-filled. On a database that already has a change, nothing runs.
- Chat and dental-school tables and columns are created for schema compatibility only; no features.

Data plumbing only, four lines each; no behavior change.

### Verifier and markers

- `SchemaVerifier`: two embedded references. The default (`ReferenceVersion`, `ReferenceResourceName`, `GetReference()`, `ReadReferenceDdl()`, `VerifyDatabase()`, `DocumentedExceptions`) is now 26.1.70; the 25.3.48 reference stays under explicit names (`GetReference25_3_48()`, `VerifyDatabase25_3_48()`, `ReferenceResourceName25_3_48`), because the 25.3 steps read definitions from it and an office copy must match it before adoption. The documented exceptions are the same for both (office customization, HQ-only and legacy tables).
- `OdSchemaCompat` becomes `26.1.70` (the adapter writes the verifier's reference version after a full match). The adoption allowlist is unchanged (24.3.63, 25.3.48): an office 25.3.48 database is adopted, then runs every M1 and M2 step (tested).

## INFERRED behaviours

The published documents give names, order and types only. Everything below is inferred from the conventions of the 25.3.48 schema and marked in the reference file.

- `NOT NULL` with no column default on every new column, except: datetime columns `NOT NULL DEFAULT '0001-01-01 00:00:00'`; `paysuitepayment.PaymentDate` `DEFAULT '0001-01-01'`; `procnote.Signature2` `text DEFAULT NULL` (as `Signature`); `evaluation.GradeOverride` and `schoolcourseenrollee.GradeNumber`/`GradeOverride` `DEFAULT -1` (the documents say "-1 by default"; it may be only a code default in Open Dental).
- `procnote.SigIsTopaz2` is `tinyint(3) unsigned NOT NULL`, as `SigIsTopaz`: the document prints plain `tinyint`, which its tool uses for unsigned tinyint columns.
- Type changes keep the old column's nullability and default (`insverify`, `insverifyhist`, `referral`, `branding`).
- `claimpayment.Note` becomes `text NOT NULL` (as Open Dental's other varchar-to-text widenings in 25.3.48, for example `histappointment.ProcDescript`); the 25.3 and 26.1 documents say text but not the nullability.
- Keys: one plain key named after each new foreign-key column (`Etrans835AttachNum`, `Title`, `UserNum2`, `SecUserNumEntry`, `SchoolCourseDefNum`, `GradingScaleNum`, and in the new tables `PaySuitePaymentDetailNum`, `ClaimPaymentNum`, `SchoolCourseNum`, `StudentNum`, `InstructorNum`); none on `deletedobj` and `paysuitepaymentdetail` besides the primary key.
- All new columns are at the end of their tables, in the published order (checked against both documents).
- `SmsToMobile.SecUserNumEntry` is `ExcludeFromUpdate` in the CRUD, like the other `SecUserNumEntry` columns.
- `DefCat.EmployeeTitles` has the description "Employee Titles", so it shows in the Definitions window with the default options until M2-02 configures it.
- The 26.1 document describes 26.1.0. Changes made in later 26.1.x patches, up to 26.1.70, have no published document and are not covered.

## Deviations from the backlog and specs

- No 26.1 reference install (owner decision): the reference comes from the published documents only.
- Reference file in `OpenDentBusiness/Misc/ForkMigrations/Reference/` instead of `docs/specs/reference/` (see above).
- `v25_4-misc-enum-parity` asks that an unknown `StatementType` fall back to NotSet "with a log line". The generated CRUD already falls back to NotSet, without a log line; generated code is not hand-edited.
- The backlog says the adoption allowlist is extended only after the verifier passes; the task keeps it as it is, so no 26.1 Open Dental database can be adopted.

## Interplay with packages built at the same time

The packages below build on these columns without having them on their base. At integration, keep M2-01's table-class fields, CRUD and steps, and drop any duplicate a feature package added for the same column; if a feature package wrote its own `ALTER` for one of these columns with a different definition, the verifier will report it.

- M2-02 (registries): `DefCat.EmployeeTitles` setup in `Defs.cs`, `DefL.cs`, `FormDefinitions.cs`; the enum values listed above under `v25_4-misc-enum-parity`. If M2-02 also added `EmployeeTitles=56` to `Def.cs`, keep one.
- M2-EMP: `employee.Title`, `DefCat.EmployeeTitles`. M2-ADJ: `definition.Supp`. M2-SDV: `statement.IsServiceDateView`. M2-DUN: `dunning.EmailType` (`EmailType` enum). M2-INSV: `insverify.DateLastAssigned` as datetime (CRUD now keeps the time). M2-ERA: `claimproc.Etrans835AttachNum` (note `ClaimProc.Equals` does not compare it, so a change of only that field does not count as a change there). M2-HIST: the three `codegroup` columns. M2-CARRIER: `carrier.PreAuthCodes`, `inseditlog`/`inseditpatlog` `*ValueBig`. M2-SHEETS / M2-EF: `sheet.DateTimeSubmitted`, `eform.DateTimeSubmitted`, `eformfield.DateTimeSig`. The procedure "Do Not Bill Insurance" item: `procedurelog.NoBillIns`. M2-MISC: `referral.Telephone` width (any 10-digit check in the UI is theirs).
- M2-NOTES: the second signature. `ProcNote.UserNum2/Signature2/SigIsTopaz2` and `Procedure.UserNum2/Signature2/SigIsTopaz2` exist and the two join queries load them. Saving a second signature (the compare-and-insert in `Procedures.Update`, the `SELECT * FROM procnote` readers) is M2-NOTES' work.
- V-PAYSUITE: `paysuitepayment`, `paysuitepaymentdetail`, `carrier.PaySuiteTransSup` and their enums exist with CRUD; reuse them. V-GP: `payterminal.CCIntegration`.
- Excluded features (chat, dental school, HQ clinic access, `deletedobj` writers): schema only, nothing reads or writes them.
- Feature data steps of other packages: a step with a level below 2026102401 that writes one of the changed tables through the CRUD will fail on a database coming from 24.3 or 25.3.48, because the CRUD writes 26.1 columns before step 2026102401 adds them. Such steps should use plain SQL with column lists, or take a level above 2026102403.
- Tests of other packages that build scratch databases from `OdSchema-25.3.48.sql` (or `GetReference25_3_48()`) and then use the CRUD on a changed table will fail after the merge for the same reason; they should use `OdSchema-26.1.70.sql` or `SchemaVerifier.GetReference()`. Existing tests changed for this are listed under "Files touched".
- Plain SQL inserts that leave out a new NOT NULL column (for example `ProcButtons.cs` into `definition`) rely on the blank `sql_mode` that OpenDental.exe sets, as Open Dental's own code does.
