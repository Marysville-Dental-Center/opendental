# Port note: S2-4 (release tooling for packages)

Package S2-4 of stage 2 of the .NET 10 move ([docs/specs/net10-plan.md](../specs/net10-plan.md), the S2-4 row): branch `net10/s24-1` from
`main` (`227d2913f`, with S2-1, S2-2 and S2-3 merged). It finishes stage 2. `tools/Build-Release.ps1` no longer takes the third-party files of
NuGet packages from `Required dlls`: it compares each staged one with the package's own file at the version the program's lock file names, so
a file that is not exactly that file fails the release. `Required dlls` loses the 30 files the packages supply, `vcruntime140.dll` and
`System.Security.Cryptography.Pkcs.dll`; what is left there has no package. `THIRD-PARTY-NOTICES.txt` names the versions the lock files name.
The tests that pinned `Required dlls` compare with the packages' own files instead. No program code, no project reference, no package version
and no schema change; nothing was downloaded; no program was started.

Commits: `d6c749088` (Build-Release), `f71b0575f` (the deletions), `859811c6f` (the notices), `150e64a74` (the tests), `c4166f622` (the docs),
`727da0a88` (a message detail of the new check), and this note.

## 2. The new release check (`tools/Build-Release.ps1`)

- **`$ThirdPartyFiles`** names each third-party file with its source: `'package:<id>'` for the 30 files of packages, `'Required dlls'` for the
  8 shipped files that stay there (the Direct Project, SharpDX, Tao), and the project output for RdlEngine, RdlViewer and the source builds
  (unchanged). The order and the names are those of `main`, so `-ListFiles` prints the same 81 lines.
- **`Get-ProgramPackageFiles`** reads `OpenPmsDental\packages.lock.json` (each package's resolved version and content hash; a package named at
  two versions is a problem) and the program's restore, `OpenPmsDental\obj\project.assets.json`: the runtime and native assets of every
  target (lib\net4x of .NET Framework 4.8, runtimes\win-x86\native of the win-x86 target), which are the files the SDK copies into the output,
  and the global packages folder the restore used (`packageFolders`). A package of the restore at another version than the lock file's, or not
  in it, is a problem; so are two packages with a file of one name. The offline folder is the one the build restores from
  (`Initialize-BuildEnvironment`: `OPMS_NUGET_OFFLINE`, else `od-tools\nuget-packages` of the common git folder).
- **`Test-PackageFiles`** (part of `Test-StagingFolder -Full`, the check every release runs on its staging folder): for each staged file of a
  package, the program's restore must copy a file of that name from the package the list names; the staged file must be byte for byte (SHA-256)
  that asset of the package in the global packages folder, whose `.nupkg.metadata` must hold the lock file's content hash, and in the offline
  folder, wherever the package is; at least one of the two must hold it. A file of another version fails with:
  `Not the package's file: Microsoft.Extensions.Logging.Abstractions.dll (file version 8.0.1325.6609) differs from lib/net462/Microsoft.Extensions.Logging.Abstractions.dll of the NuGet package Microsoft.Extensions.Logging.Abstractions 10.0.15 (file version 10.0.1526.53008), the version OpenPmsDental\packages.lock.json names: <the package's file in the global packages folder>; <and in the offline folder>`.
  The other problems it reports: `No package for:`, `Another package:`, `Not the locked package:` (content hash), `Not in the package:`,
  `Package not found:`, `No restore of the program:`, `No lock file:`.
- **`-CheckFolder <folder> -Full`** (new switch): the staging checks of a release, including this one, on any folder. `-CheckFolder` alone
  stays the list checks.
- **`$NativeFiles`** keeps `WebView2Loader.dll`'s x86 and debug-runtime check; the file is now the package's `runtimes\win-x86\native` loader
  (an x64 or arm64 loader of the same package fails it).
- The `Required dlls` comparison stays for the 8 shipped files that are still there, and the project-output comparison for the files built here.
