## 2. The conversion (`tools/Convert-TestProjectsToSdk.ps1`)

The script is committed under `tools/` rather than kept here: it stays useful until the stage 1 gate, in case a package that ran at the
same time brings a change to a classic test project file in a merge. TC-2 did: it merged into `main` first, and its classic
`ToothChartImageTests.csproj` was converted again with this script when `main` was merged into this package (section 4). For a later
merge (DB-TLS) the same applies: put that branch's classic file in place, run the script on it and take its output, rather than this
package's file as it is, which would lose a new reference or item with metadata (section 7). After the stage 1 gate it can be deleted.

For each classic test project it writes a project file with only what differs from the SDK's defaults and from `tests/Directory.Build.props`:

- **Kept:** every comment of the project file (the description, and the comment in front of each item or property it keeps); `OutputType`,
  `RootNamespace` and `AssemblyName` where they differ from the defaults (UnitTests: `WinExe`, `Unit Tests`); `LangVersion` where it is
  not 8.0 (CryptoTests, ImagingCaptureTests, ImagingDeviceManagerTests, ProjectFileTests and UnitTests: 7.3); `ApplicationManifest`
  (UnitTests); every `Reference` with a `HintPath` or other metadata and every framework `Reference` the SDK does not add itself; every
  `ProjectReference` (without the `Project` and `Name` metadata, which only the classic project system reads); the linked `Compile`
  items from outside the folder (36 `..\ForkMigrationTests\TestDb.cs`, 30 `..\ProjectFileTests\ProjectFile.cs`, 6
  `..\ProjectFileTests\BuildOutput.cs`, each with its `Link`); a `Compile Update` or `EmbeddedResource Update` for every item in the folder
  that carries metadata other than `SubType` (UnitTests' designer files and form resources with `DependentUpon`, its generated
  `Resources` and `Settings` files); every `None` and `Content` item (the copied data files of M202Tests, M2INSPLANTests and RegistryTests,
  the linked `WebView2Loader.dll` of LibWebTests and M2IMGTests, UnitTests' own).
- **Replaced:** the Mono.Cecil `HintPath` references into `packages\Mono.Cecil.0.10.3` (LibraryBindingTests, LibWebTests,
  MiddleTierMockTests: `Mono.Cecil`; UnitTests: `Mono.Cecil`, `.Mdb`, `.Pdb` and `.Rocks`) by one `<PackageReference Include="Mono.Cecil"
  Version="0.10.3" />`, with the comment that named `packages.config` rewritten. MiddleTierMockTests, which the S1-6 row does not name,
  had the same `HintPath` and a `packages.config` of its own.
- **Dropped:** the `**\*.cs` item (NETSDK1022 otherwise) and every `Compile` and `EmbeddedResource` item the default globs give; `SubType`;
  the MSTest v1 reference (in `tests/Directory.Build.props`); the framework references the SDK adds by itself (`System`, `System.Core`,
  `System.Data`, `System.Drawing`, `System.Xml`, `System.Xml.Linq`, `System.Runtime.Serialization`, `System.Numerics`,
  `System.IO.Compression.FileSystem`); `ProjectGuid`, `ProjectTypeGuids`, `IsCodedUITest`, `TestProjectType`, `AppDesignerFolder`,
  `FileAlignment` and the other properties equal to the SDK's or the shared files' values; UnitTests' ClickOnce and bootstrapper settings,
  `BootstrapperPackage` and `Service` items, `ResGenToolArchitecture`, its LinuxRelease and AnyCPU configurations and the template comment
  at its end; the `packages.config` `None` items.
- **Special cases:** BMEDTests and SheetTests defined no `DEBUG` symbol in their Debug configuration (`TRACE` only); they set
  `DefineConstants` `TRACE` and `DisableImplicitConfigurationDefines`, so the SDK adds no `DEBUG` (and no `RELEASE`) either. CryptoTests and UnitTests, which the solution
  also builds as Any CPU, set `Platforms` to `AnyCPU;x86`. CryptoTests and UnitTests had no description comment and got one; the comments of
  EhrTests and ToothChartImageTests ("Compile items are listed one by one until S1-6 converts this file") now say every `.cs` file is
  compiled.
- **Checks before it writes:** a property it does not know or with another value than expected, an item type or metadata it does not
  know, and a `.cs` or `.resx` file under the folder that the classic project did not compile or embed (the glob would add it) stop it.
  CryptoTests, EhrTests, ToothChartImageTests and UnitTests listed their files one by one; every file under their folders was listed.

**UnitTests and the two tools tests (outside `tests\`).** MSBuild imports the nearest `Directory.Build.props`, which for them is the
repository's, not `tests/Directory.Build.props`. They name `tests\Directory.Build.props` as their `DirectoryBuildPropsPath`, set before an
explicit `Sdk.props` import (so the project uses `<Project>` with `Sdk.props` and `Sdk.targets` imports, as OpenPmsDental does);
`tests/Directory.Build.props` imports the repository's file first, so each of the two files is imported once and stages 2, 4 and 3b reach
these three projects through the one shared file too. The other choice, carrying the same settings in the project as NoHqTests does since
S1-5, was not taken for that reason. NoHqTests and UnitTestsCore (S1-5) are unchanged.

## 3. `tests/Directory.Build.props`

For SDK-style projects only, as before (no classic project is left among the tests; the Middle Tier project is not a test project):

- `GenerateBindingRedirectsOutputType=true` beside `AutoGenerateBindingRedirects=true` (the S1-6 row): `Microsoft.Common.CurrentVersion.targets`
  sets it only for an exe or winexe, and the test projects are libraries that set it in their own files until now; LibraryBindingTests'
  `TestProjects_GenerateTheirRedirects_FromTheSharedTestConfig` checks both.
- `Platforms` x86, `LangVersion` 8.0, and `DebugType` full for Debug and pdbonly for Release: the values almost every classic test project
  had (the SDK's defaults are AnyCPU, 7.3 for net48 and portable).
- `EnableDefaultNoneItems=false`: a test project's `None` items are the ones it lists, as before. Otherwise every other file under a test
  folder would be a `None` item (about 2,000 baseline pictures of ToothChartImageTests, the fixtures of ProjectFileTests, the lock file),
  which builds nothing but changes the evaluated items. The `Compile` and `EmbeddedResource` globs stay on.
- `DisableTransitiveProjectReferences=true`: a test project references the projects it names, as before. With the SDK's transitive
  project references (the first build of this package), the 27 test projects that reference the program (UnitTests and 26 under
  `tests\`) also got ODR and OpenPmsDentalDbSettings in their output folders: 135 files, 27 of them `OpenPmsDentalDbSettings.exe.config`,
  because the program references both as projects although its assembly references neither. Their test lists and fingerprints were the
  same either way; without the setting every test folder holds the files it held, and the compiler gets the classic references plus the
  SDK's implicit framework ones.
- The header comment says which projects get the file and how; the stale clause "the repository's file turns them off for a project that
  does not ask" (true until the 2026-11-08 sweep) is gone.

MSTest v1 stays referenced by name and resolves through `Directory.Build.targets`' `ODAddMSTestV1SearchPath` in every converted project
(`Common7\IDE\Extensions\TestPlatform` of the Build Tools 2026); no `HintPath` was needed.
