## What Open PMS - Dental is

A Windows practice management program for dental offices: charting, scheduling, accounts and billing, insurance and claims, imaging and reports. It is written in C# (WinForms, with some WPF) on .NET Framework 4.8 and keeps its data in the office's own MariaDB server.

It is built from Open Dental's public source code, version 24.3.63.0, and is fully independent of Open Dental Software, Inc.:

- It never contacts Open Dental's servers: no eServices, no update server, no support or registration keys, no telemetry.
- It contains no Open Dental proprietary binary. Everything it runs is built from this repository or is a third-party component listed, with its licence, in `THIRD-PARTY-NOTICES.txt`.
- Everything runs locally. The database, the images (the A to Z folder) and the updates stay on the office's network.

## What v0.0 contains

- **Open Dental features up to 26.1, re-implemented from public sources.** Features of Open Dental 24.4, 25.1, 25.2, 25.3, 25.4 and 26.1 were rebuilt from Open Dental's public manual and release notes; no Open Dental binary was decompiled. The 25.3 feature level comes first, so an office can switch over from Open Dental 25.3.48. The database schema follows Open Dental 26.1.70. Among the areas: insurance code groups and Insurance History, the estimate engine, Edit Insurance Plan, the Insurance Verification List, ERA auto split and filters, the related-claims prompt, the Denti-Cal claim form, payment plans and the Payment window, percent-of-fee adjustments, sales tax, the Service Date View and HTML dunning statements, recurring charges, eForms, sheets in non-Latin scripts, appointment and blockout permissions, time cards and employee titles, procedure and group notes, the perio chart, the wiki's read-only copy, Database Maintenance tools and the UDS+ report. Each package has a note in `docs/port-notes/`.
- **Decoupled.** Open Dental's hosted services and HQ calls are removed, not replaced by stand-ins. Releases reach the office's workstations through the program's own release channel, stored in the office database (see "Updates" below). A version guard keeps the program from converting a database it does not know.
- **Vendor-neutral.** An integration shows its buttons and windows only after the office turns it on. There are no advertisements, partner promotions or sign-up links. Integrations that Open Dental routed through its own servers call the vendor directly from the office where the vendor allows that (for example QuickBooks Online, Microsoft 365 e-mail and USPS address checks). Every online integration is optional and off until the office sets it up.
- **Native capture.** Open source TWAIN scanning (`ImagingDeviceManager`), the capture session for X-ray sensors and intraoral cameras (`ImagingCapture`), DICOM thumbnails, cropping and rotation, and an in-house reader for the simple DICOM files the capture writes. See `docs/imaging-capture-design.md`.
- **A new office database.** `db/init/new-database.sql` creates the database a new office starts from (see "Creating a new database").
- **The workstation installer**, described below.

## What v0.0 does not contain

- **The office switch-over as an installer.** Adopting an existing Open Dental database (24.3.63 or 25.3.48) is a separate, supervised procedure: `docs/adoption-runbook.md` and `tools/AdoptionValidation`. The workstation setup never adopts or changes a database.
- **The side programs:** the HL7 service (`OpenPmsDentalHL7`), the Middle Tier server (`OpenPmsDentalServer`), CentralManager, DatabaseIntegrityCheck, MySQLManager and the replication service. They are in the source but not in the setup. (`ServiceManager.exe` and `UpdateFileCopier.exe` are installed: the program uses them.)
- **Excluded features:** Open Dental's hosted services (eClipboard, ODTouch, Web Sched, Web Forms, integrated texting, Secure and Mass E-mail, the Payment Portal, automated messaging, the eConnector), HQ support and licensing, Open Dental Cloud, the local REST API, dental school features, intra-office chat, CareCredit, and the licensed fee guides Open Dental delivers. The list with reasons is in `docs/specs/port-backlog.md` ("Excluded").
- **Removed with Open Dental's closed binaries:** Suni direct capture (Suni sensors work through Suni's TWAIN driver), the Sparks3D tooth chart (the chart draws with DirectX 9, OpenGL or Simple 2D), and four bridges that now say "not available": Dr. Ceph, eClinicalWorks Rx, Patterson Imaging and Schick CDR 4 (Schick CDR DICOM still works).
- **ADA content:** no CDT descriptors and no ADA claim form artwork. Procedure codes are named by their code until the office imports its licensed CDT file.
- **Plug-ins built for Open Dental** do not load.

## Prerequisites

Each workstation:

- Windows 10 version 1903 or later, or Windows 11.
- **.NET Framework 4.8.** Windows 10 1903 and later and Windows 11 have it. Setup stops with a message if it is missing.
- **Microsoft Visual C++ 2015-2022 Redistributable (x86)** and the **Microsoft Edge WebView2 Runtime**. When either is missing, setup offers to download Microsoft's own installer from Microsoft (aka.ms and go.microsoft.com), checks its Microsoft signature and runs it, or to skip it with a warning. Without the Visual C++ runtime, DICOM images and the Direct2D drawing fail; without WebView2, every window that shows web content fails.
- For scanners and sensors: the device's own TWAIN driver.
- Optional: Microsoft's DirectX End-User Runtime (`d3dx9_43.dll`) for the DirectX tooth chart and the graphical perio chart. Without it the tooth chart uses OpenGL.

The database server (installed by the office, never by this setup): MariaDB 10.11 with `sql_mode=` blank, `default-storage-engine=MyISAM` and `max_allowed_packet=40M`, a database account of the office's own, and backups. See README.md, "Database server".

## Installing

1. Check the download: `Get-FileHash .\OpenPmsDental-0.0-Setup.exe -Algorithm SHA256` must print the value `SHA256SUMS.txt` gives for it.
2. **Install on the update server first** (the workstation named in Setup > Update Setup, `WebServiceServerName`; see "Updates").
3. Run the setup as an administrator. Windows SmartScreen may say it protected the PC, because the setup is not signed: choose More info, then Run anyway, after checking the SHA-256. The wizard shows:
   - the GNU GPL;
   - an information page with the attribution, the source address and NOTICE;
   - the folder, `C:\Program Files (x86)\Open PMS - Dental` (a new or empty folder, or an earlier installation of this program; setup refuses a folder that holds other files);
   - an optional desktop shortcut;
   - **Database connection**: server (host, or host:port for a port other than 3306), database and user. Setup writes them to `FreeDentalConfig.xml` in the program folder, never a password, and lets standard users change that one file. The page is skipped when the folder already has a `FreeDentalConfig.xml`, which is kept as it is;
   - Microsoft components, only when some are missing.
4. Start **Open PMS - Dental** from the Start menu. The Choose Database window shows the setup's values: enter the database password. On the update server the program then offers to publish its release, so the other workstations update to it.
5. Install the other workstations the same way.

Setup also registers the program's Event Log source (`OpenPMS-Dental`). It never starts the program.

**Silent install**, for example for several workstations:

```
OpenPmsDental-0.0-Setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /DBSERVER=dbserver /DBNAME=opendental /DBUSER=opms /PREREQS=download /LOG="C:\Temp\opms-setup.log"
```

| Switch | Meaning |
|---|---|
| `/DBSERVER=`, `/DBNAME=`, `/DBUSER=` | The database connection page (defaults `localhost`, `opendental`, `root`). Used only when the folder has no `FreeDentalConfig.xml` |
| `/PREREQS=download` | Download and install a missing Visual C++ or WebView2 runtime from Microsoft. `skip` skips them; a silent install skips them unless told otherwise, and logs a warning |
| `/DIR="folder"` | Another program folder |
| `/TASKS=desktopicon` | Also a desktop shortcut |
| `/NOICONS` | No Start menu shortcut |
| `/LOG="file"` | The setup log |
| `/CURRENTUSER` | Install without administrator rights, for tests only (no Event Log source) |

Exit code 0 means installed. Any other exit code means nothing was installed, or the installation did not finish; the log says why (for example: .NET Framework 4.8 is missing, the folder holds other files, or a database connection value was refused).

**Uninstall:** Settings > Apps > Open PMS - Dental, or `"C:\Program Files (x86)\Open PMS - Dental\uninstall\unins000.exe" /VERYSILENT`. It removes the whole program folder, including files that updates added after setup, the shortcuts and the Event Log source. It never touches the database or the A to Z folder; a folder inside the program folder that looks like an A to Z folder (one folder per letter) is left where it is.

## Updates

New builds reach the workstations through the program's own release channel (`docs/release-process.md`). The order matters:

1. Install the new build on the **update server** first and start it as an administrator. It publishes the release into the office database.
2. Every other workstation pulls the published release at its next start and restarts through `UpdateFileCopier.exe`.

A workstation that is not the update server refuses to run a build newer than the published one (exit code 174), so the setup is only for new workstations and for the update server. After a pull, Programs and Features still shows the version the workstation was installed with. Debug builds never publish or pull. A development install from before the rename (whose exe had Open Dental's file name) is not upgraded in place: install into a new folder.

## Known limitations

- **The setup is not signed** (decided for v0.0), so SmartScreen warns about it. Compare its SHA-256 with `SHA256SUMS.txt`.
- **Partner-gated vendor features.** Some integrations need the vendor's partner access, interface documentation or test login before they can be turned on: for example Global Payments Cloud Integration, EDS's 26.1 checks, DTX Studio, Overjet, Clerri, Clever One, and the four bridges above. They stay off or say "not available" until then. `docs/owner-questions.md`, "Vendor integrations", lists what each one waits for.
- **16-bit X-rays are not for patient use** until the counsel review and the clinic run are done. Computers that capture for patients stay at 8 bits (`Allow16Bit=0`). See `docs/imaging-capture-owner-questions.md`, the items marked [BEFORE PATIENT USE] and [BEFORE 16-BIT].
- **Nothing has run on real sensor or camera hardware yet.** The capture work is tested with synthetic images and simulated devices only.
- **Licence questions are open** for three components the release still ships: fo-dicom (MS-PL), NDde (its own shared source licence) and the Google APIs client libraries (Apache 2.0, which fits GPL v3 but not v2). See `docs/owner-questions.md`.
- The setup was test-installed per user on a development PC only. The administrator install, the Event Log source and the download of the Microsoft components have not run on an office PC yet, and the program has not been started from an installed folder.
- The DirectX tooth chart and the graphical perio chart need Microsoft's DirectX End-User Runtime, which the setup does not install.

## Creating a new database

`db\README.md` and `db\init\new-database.sql` are in the program folder, and in the repository. In short: install MariaDB 10.11 with MyISAM as the default engine, create an empty database (`CREATE DATABASE opendental CHARACTER SET utf8mb3 COLLATE utf8mb3_general_ci;`), load the file into it with the `mariadb` client or HeidiSQL, point the program at it (the setup's database connection page does that), start the program, log on as `Admin` and set a password at once, then enter the practice's settings. The file holds no patients and no CDT descriptors.
