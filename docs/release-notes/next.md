# Open PMS - Dental: release notes of the next version

Each section below was written by the package that made the change; the sections stand on their own.

## DICOM: fo-dicom is gone, the program reads DICOM itself

fo-dicom 4.0.7, the DICOM library Open Dental shipped (`Dicom.Core.dll` and `Dicom.Native.dll`, under the Microsoft Public License, which is not compatible with the GNU GPL), is no longer part of the program. Every DICOM image is now read by the program's own reader, written from the DICOM standard (NEMA PS3) alone. The design is in `docs/imaging/dicom-reader.md`.

- **What opens as before.** Every DICOM file that version 0.0 showed opens, and shows the same, pixel for pixel, apart from the two corrections and the safeguards below: the program's own 16-bit X-rays, and files from other programs in Implicit VR Little Endian, Explicit VR Little Endian, Explicit VR Big Endian or Deflated Explicit VR Little Endian, with or without the 128-byte preamble, including files whose header breaks the standard in ways version 0.0 put up with (an Implicit VR data set labelled Explicit VR, blank VR fields, a File Meta Information header in Implicit VR, a preamble without the "DICM" marker), gray (MONOCHROME1 and MONOCHROME2, 8, 12 and 16 bits) or RGB color shown in gray, the first frame of multi-frame files, and RLE Lossless and JPEG Baseline compression, progressive JPEG included. Brightness and contrast, thumbnails, mounts, cropping, printing, e-mail and the 8-bit JPEG copy attached to claims work as before.
- **What opens now and did not before.** Signed images (such as CT exports), bit depths other than 8, 12 and 16 (for example 10 or 14 bits), YBR_FULL, YBR_FULL_422 and palette color images, color JPEG Baseline images whatever color space they are labelled with, and Encapsulated Uncompressed files. 16-bit color and signed 8-bit images, which version 0.0 showed scrambled, now show correctly (the two corrections).
- **Safeguards.** A file built to keep a DICOM reader busy for minutes is refused with a message instead of freezing the Imaging module: more than a million elements, a deflated file whose data before the pixels inflates past 64 MB, or a JPEG image of more than 32 scans. Ordinary images come nowhere near these limits (a progressive JPEG has about ten scans), but version 0.0 would have tried to open such files.
- **Compressed formats that open in this version:** RLE Lossless, JPEG Baseline (Process 1, the usual "lossy JPEG" of DICOM) and Encapsulated Uncompressed.
- **Compressed formats that do not open yet:** JPEG Extended (12-bit JPEG), JPEG Lossless, JPEG-LS, JPEG 2000, High-Throughput JPEG 2000 (HTJ2K), JPEG XL and DICOM video. Version 0.0 opened JPEG Extended, JPEG Lossless, JPEG-LS and JPEG 2000 through fo-dicom's native codecs; this version does not. Opening such an image in the Imaging module says which format it is and that this version cannot open it yet, instead of showing an image; a mount names it next to the mount position. The image is never changed or lost: it can still be imported and stays in the patient's images, and a later version with a decoder for its format opens it. An office that receives such images from another program (for example a CBCT or panoramic unit that exports JPEG 2000) can ask that program to export uncompressed or JPEG Baseline DICOM in the meantime.
- **Upgrading.** Setup removes `Dicom.Core.dll` and `Dicom.Native.dll` from the program folder. The Visual C++ runtime is still needed, by `Direct2dWrapper.dll`.
- **Licences.** `THIRD-PARTY-NOTICES.txt` no longer lists fo-dicom, and the program's license list no longer carries the MS-PL.
